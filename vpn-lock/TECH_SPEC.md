# Техническое задание: Программа VPN Lock

## 1. Общие положения

### 1.1. Наименование
Набор скриптов далее именуется как **Программа**.

### 1.2. Назначение
Программа предназначена для предотвращения доступа к заданным ресурсам при выключенном VPN-соединении.

### 1.3. Цель
Обеспечить автоматическую блокировку доступа к заданным доменам и связанным с ними сетевым адресам, если целевое VPN-соединение не активно, и автоматически снимать блокировку при активном VPN-соединении.

## 2. Термины

- **Программа**: набор установочных и системных скриптов, обеспечивающих контроль доступа к ресурсам.
- **VPN-соединение**: заранее заданное VPN-подключение, статус которого отслеживает Программа.
- **Защищаемые ресурсы**: список доменов, доступ к которым должен блокироваться при неактивном VPN.
- **Статус подключения**: состояние целевого VPN-соединения: активно или неактивно.
- **Защита**: режим блокировки доступа к защищаемым ресурсам.

## 3. Область применения

Программа предназначена для Linux-систем, где доступно:

- управление системными службами;
- автоматический запуск при старте системы;
- обработка событий сети;
- обработка выхода из спящего режима.

Если не оговорено отдельно, целевая среда предполагает использование `systemd` и `NetworkManager`.

## 4. Функциональные требования

### 4.1. Конфигурация

Программа должна поддерживать настройку следующих параметров:

- имя VPN-соединения, за состоянием которого ведётся контроль;
- список защищаемых доменов;
- системные параметры, необходимые для применения и снятия блокировки;
- путь к журналу работы Программы.

### 4.2. События запуска проверки

Программа должна запускать проверку статуса VPN-соединения и приводить защиту в актуальное состояние в следующих случаях:

- при установке Программы;
- при старте компьютера;
- при перезагрузке компьютера;
- при выходе компьютера из спящего режима (`resume after suspend`).

Дополнительно Программа должна реагировать на изменение состояния VPN-соединения во время работы системы:

- при установлении VPN-соединения;
- при разрыве VPN-соединения.

### 4.3. Логика работы

При активном VPN-соединении:

- Программа должна полностью снимать защиту;
- доступ к защищаемым доменам должен быть разрешён.

При неактивном VPN-соединении:

- Программа должна включать защиту;
- доступ к защищаемым ресурсам должен быть заблокирован.

### 4.4. Принцип безопасности

Программа должна работать по принципу `fail closed`:

- если статус VPN не удалось определить, защита должна считаться включённой;
- если при обновлении данных для блокировки произошла ошибка, доступ не должен открываться автоматически;
- после перезагрузки или выхода из сна защита не должна оставаться снятой, если VPN не активен.

### 4.5. Установка

При установке Программа должна:

- установить необходимые системные компоненты и зависимости;
- разместить исполняемые скрипты и конфигурационные файлы;
- зарегистрировать механизмы автозапуска;
- выполнить первичную проверку статуса VPN;
- сразу применить корректный режим защиты;
- не завершаться с ошибкой, если часть зависимостей, файлов, правил или системных компонентов уже установлена;
- поддерживать повторный запуск инсталлятора для переконфигурации Программы без необходимости ручного удаления предыдущей установки.

### 4.6. Логирование

Программа должна вести журнал событий. В журнале должны фиксироваться как минимум:

- запуск Программы;
- результат проверки статуса VPN;
- включение защиты;
- снятие защиты;
- ошибки при определении статуса VPN;
- ошибки при обновлении данных, необходимых для блокировки.

## 5. Требования к поведению

### 5.1. При включённом VPN

Ожидаемое поведение:

- защита отключена;
- доступ к защищаемым доменам доступен;
- ранее созданные правила блокировки не должны мешать доступу.

### 5.2. При выключенном VPN

Ожидаемое поведение:

- защита включена;
- доступ к защищаемым доменам отсутствует;
- блокировка должна применяться автоматически, без участия пользователя.

### 5.3. После загрузки системы

Ожидаемое поведение:

- Программа стартует автоматически;
- проверяет статус VPN;
- применяет блокировку или снимает её в зависимости от результата проверки.

### 5.4. После выхода из сна

Ожидаемое поведение:

- Программа повторно проверяет статус VPN;
- если VPN активен, защита снимается;
- если VPN неактивен, защита включается или остаётся включённой.

## 6. Ограничения и допущения

- Программа не должна требовать ручного запуска после установки.
- Программа не должна требовать действий пользователя при каждой загрузке системы.
- Программа должна корректно обрабатывать повторный запуск.
- Программа должна сохранять работоспособность после перезагрузки.
- Список защищаемых ресурсов задаётся пользователем или администратором на этапе настройки.

## 7. Критерии приёмки

Задача считается выполненной, если одновременно выполняются следующие условия:

1. После установки Программа автоматически определяет статус VPN и применяет корректный режим защиты.
2. После старта или перезагрузки компьютера Программа автоматически восстанавливает корректное состояние защиты.
3. После выхода из спящего режима Программа автоматически повторно проверяет статус VPN и корректирует режим защиты.
4. При активном VPN доступ к защищаемым доменам есть.
5. При неактивном VPN доступ к защищаемым доменам отсутствует.
6. При подключении VPN в работающей системе защита снимается без ручного вмешательства.
7. При отключении VPN в работающей системе защита включается без ручного вмешательства.
8. Повторный запуск инсталлятора не приводит к аварийному завершению, если Программа или её зависимости уже установлены.
9. Повторный запуск инсталлятора позволяет изменить конфигурацию Программы и применить обновлённые параметры.
10. Основные действия и ошибки фиксируются в журнале.

## 8. Результат разработки

Результатом выполнения задачи должен быть комплект скриптов и конфигурации, который:

- устанавливается в систему;
- автоматически запускается в требуемые моменты;
- контролирует статус заданного VPN-соединения;
- блокирует доступ к заданным ресурсам при выключенном VPN;
- снимает блокировку при включённом VPN.
