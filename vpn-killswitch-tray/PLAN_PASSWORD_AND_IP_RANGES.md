# План: один запрос пароля и IP-диапазоны

## Цель

Исправить два пользовательских сценария в `vpn-killswitch-tray`:

- при сохранении изменений в редакторе не должно быть много запросов пароля;
- bypass-список должен принимать домены, одиночные IPv4, CIDR и диапазоны IPv4.

Главный критерий: одно нажатие «Сохранить» в редакторе должно требовать не больше одного `pkexec`.

## 1. Зафиксировать контракт tray -> CLI

Статус: выполнено.

Добавить в core CLI `vpn-killswitch` пакетную команду для сохранения из tray:

```bash
vpn-killswitch config apply-tray --enforce
```

Ожидаемое поведение:

- команда принимает полный желаемый состав списков или дельту изменений;
- валидирует все записи до изменения конфига;
- обновляет конфиг одним действием;
- при `--enforce` сразу применяет правила;
- возвращает понятный результат для tray;
- весь сценарий выполняется внутри одного привилегированного процесса.

Предпочтительный формат передачи данных: JSON через stdin.

## 2. Расширить модель bypass в core CLI

Статус: выполнено.

Добавить поддержку явных IPv4-записей в конфиге `vpn-killswitch`:

```toml
[bypass]
domains = ["ozon.ru", "wildberries.ru"]
ips = ["93.184.216.34", "93.184.216.0/24", "93.184.216.10-93.184.216.20"]
```

Правила:

- домены остаются в `bypass.domains`;
- IP/CIDR/range хранятся отдельно в `bypass.ips`;
- IPv4 без маски трактуется как `/32`;
- CIDR применяется как один маршрут;
- диапазон `IP-IP` нормализуется во внутренний набор минимальных CIDR;
- IPv6 для этой доработки не поддерживается.

## 3. Реализовать валидацию IP-записей

Статус: выполнено.

Покрыть форматы:

```text
93.184.216.34
93.184.216.0/24
93.184.216.10-93.184.216.20
```

Ошибки должны быть понятными:

- невалидный IP;
- невалидная CIDR-маска;
- начало диапазона больше конца;
- IPv6 указан там, где разрешён только IPv4.

## 4. Обновить применение bypass-маршрутов

Статус: выполнено.

При `vpn-killswitch enforce` и `vpn-killswitch bypass apply` использовать два источника:

- `bypass.domains` через DNS-резолв;
- `bypass.ips` без DNS-резолва.

State должен позволять отличать источник маршрута:

```text
185.73.193.68/32 domain ozon.ru
93.184.216.0/24 ip 93.184.216.0/24
```

Требования:

- удалять только маршруты из собственного state;
- не раскрывать CIDR в большое количество `/32`;
- диапазоны через дефис применять как минимальные CIDR-блоки;
- не ломать чтение старого state-формата, если он уже существует.

## 5. Переделать сохранение в tray

Статус: выполнено.

Текущий проблемный сценарий:

```text
pkexec config add/remove ...
pkexec config add/remove ...
pkexec enforce tray
```

Новый сценарий:

```bash
pkexec vpn-killswitch config apply-tray --enforce
```

Tray должен:

- сравнить старый и новый состав списков;
- сформировать payload;
- выполнить один `pkexec`;
- дождаться результата;
- обновить статус;
- записать результат в tray log.

## 6. Обновить редактор tray

Статус: выполнено.

В bypass-списке разрешить:

- домены;
- одиночные IPv4;
- IPv4 CIDR;
- IPv4 range.

В lock-списке оставить только домены.

Валидация до `pkexec`:

- пустые строки запрещены;
- домены нормализуются к lowercase;
- IP-записи нормализуются;
- ошибочный IP/range показывает сообщение без запроса пароля.

## 7. Тесты

Статус: выполнено для автоматических unit-тестов.

Core CLI:

- парсинг одиночного IPv4;
- парсинг CIDR;
- парсинг диапазона `IP-IP`;
- нормализация диапазона в CIDR;
- ошибки валидации;
- пакетное обновление конфига;
- `--enforce` вызывает применение правил один раз.

Tray:

- diff списков;
- формирование payload;
- один `pkexec` на сохранение;
- отмена `pkexec`;
- ошибка валидации до `pkexec`;
- смешанный bypass-список: domain + IP + CIDR + range.

## 8. Ручная приёмка

Статус: частично выполнено headless.

Проверено:

- оба бинаря собираются;
- `pkexec` и `yad` найдены в окружении;
- `config apply-tray` принимает JSON payload;
- домены/IP/CIDR/range нормализуются и записываются в temp-конфиг;
- плохой IPv6 в `bypass_ips` отклоняется до применения.

Не проверено в этом окружении:

- реальное окно `yad`;
- реальный запрос `pkexec`;
- применение маршрутов через `ip`, потому что netlink недоступен: `Cannot open netlink socket: Operation not permitted`.

Проверить сценарии:

```text
добавить один домен в bypass
добавить несколько доменов в bypass
добавить одиночный IPv4
добавить CIDR
добавить диапазон IPv4
удалить несколько записей
сохранить смешанный список domain + IP + CIDR + range
отменить запрос pkexec
ввести плохой IP
```

Ожидаемый результат:

- сохранение редактора спрашивает пароль максимум один раз;
- плохой ввод отклоняется до запроса пароля;
- после успешного сохранения правила уже применены;
- статус tray обновлён сразу после операции.
