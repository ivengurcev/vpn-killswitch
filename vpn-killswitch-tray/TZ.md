# ТЗ: vpn-killswitch-tray

## 1. Назначение

`vpn-killswitch-tray` — пользовательское приложение для системного трея, которое показывает состояние `vpn-killswitch` и даёт простой способ добавлять/удалять домены без запоминания CLI.

Приложение не заменяет `vpn-killswitch` и не реализует сетевую логику само. Это графическое приложение-компаньон поверх установленного CLI.

## 2. Основная идея

`vpn-killswitch` остаётся системным CLI и отвечает за интеграцию с systemd.

`vpn-killswitch-tray` работает как обычное пользовательское приложение:

- периодически читает состояние через `vpn-killswitch status --json`;
- показывает состояние через иконку в трее;
- вызывает ограниченный набор команд `vpn-killswitch`;
- помогает добавить один или несколько доменов в bypass или lock через простую форму;
- помогает добавить IPv4-адреса и диапазоны в bypass.

## 3. Платформа

Целевая платформа MVP:

- Linux с графическим окружением;
- окружение X11/Wayland с системным треем/status notifier;
- установленный и настроенный `vpn-killswitch`;
- NetworkManager/systemd остаются ответственностью core CLI.

## 4. Архитектура

Компоненты:

- `vpn-killswitch` — основной системный CLI;
- `vpn-killswitch-tray` — пользовательское графическое приложение-компаньон;
- повышение привилегий — через `pkexec` на MVP.

Принцип:

- команды только для чтения можно выполнять напрямую;
- команды, меняющие систему или `/etc/vpn-killswitch/config.toml`, выполняются через `pkexec`;
- опасные команды вроде `uninstall`, `cleanup-legacy --purge` в tray не добавлять.

## 4.1 Модель состояния

Приложение в трее нормализует состояние `vpn-killswitch status --json` в одно из пяти состояний:

- `offline`: `vpn-killswitch` не найден, команда `status` упала, JSON не распарсился или истёк таймаут команды;
- `ok`: `vpn.status=active`, lock снят (`lock.nft_active=false`, `lock.hosts_block=false`), критичных ошибок нет;
- `locked`: `vpn.status=inactive|unknown`, lock включён (`lock.nft_active=true` или `lock.hosts_block=true`), критичных ошибок нет;
- `warning`: состояние неоднозначное, например VPN `inactive`/`unknown`, но lock не включён, или VPN `active`, но lock всё ещё активен;
- `error`: есть ошибки в `errors`, ошибка конфига, ошибка `install-check`/`test` или команда изменения завершилась ошибкой.

Приоритет состояний:

```text
offline > error > warning > locked > ok
```

Первое чтение состояния после старта только устанавливает базовое состояние.

## 5. Источники данных

Основной статус:

```bash
vpn-killswitch status --json
```

JSON-контракт `status --json` описан в `vpn-killswitch/TZ.md`. Tray обязан использовать только публичные поля этого контракта:

- `vpn.status`;
- `gateway.error`;
- `bypass.domain_count`;
- `bypass.route_count`;
- `lock.domain_count`;
- `lock.nft_active`;
- `lock.hosts_block`;
- `lock.error`;
- `config.path`;
- `errors`.

Диагностика:

```bash
vpn-killswitch test --json
vpn-killswitch install-check --json
```

Резолв доменов:

```bash
vpn-killswitch resolve --json
```

Логи:

```bash
journalctl -u vpn-killswitch.service -n 50 --no-pager
```

Логи в MVP можно не показывать в отдельном окне, но пункт меню «Диагностика» должен быть.

## 5.1 Отказоустойчивость

Если `vpn-killswitch` не найден:

- состояние `offline`;
- подсказка: `vpn-killswitch not found`;
- меню: «Обновить статус», «Настройки», «О программе», «Выход».

Если `pkexec` не найден:

- функции только для чтения продолжают работать;
- изменяющие действия отключены;
- подсказка/меню показывает `pkexec not found`;
- ошибка при попытке выполнить изменяющее действие пишется в лог.

Если `yad` не найден:

- редактор доменов отключён;
- меню показывает `Dialog backend not found`;
- статус только для чтения остаётся доступен.

Если пользователь отменил `pkexec`:

- команда считается отменённой, а не упавшей;
- отмена пишется в лог как штатное событие.

Если status JSON не парсится:

- состояние `offline`;
- ошибка пишется в tray log;
- одинаковую ошибку не писать чаще одного раза в 60 секунд.

## 6. Иконка в трее

Состояния иконки:

- зелёная/`ok`: VPN `active`, lock снят;
- красная/`locked`: VPN `inactive` или `unknown`, lock включён;
- жёлтая/`warning`: ошибка диагностики, ошибка конфига или противоречивое состояние;
- серая/`offline`: `vpn-killswitch` не установлен или статус не читается.

Подсказка должна показывать короткую строку:

```text
VPN: active | Lock: off | Bypass routes: 12
```

## 7. Отображение изменений

Приложение не отправляет desktop-уведомления. Основной сигнал — иконка в трее, tooltip и строка статуса в меню.

События:

- VPN стал `active`;
- VPN стал `inactive`;
- статус VPN стал `unknown`;
- lock включён;
- lock снят;
- появилась ошибка конфига или диагностики;
- домен добавлен в bypass;
- домен добавлен в lock;
- команда завершилась ошибкой.

Эти события должны отражаться через:

- смену иконки;
- обновление tooltip;
- обновление строки статуса в меню;
- запись в лог приложения.

Примеры строк лога:

```text
VPN активен: lock выключен
VPN неактивен: lock включён
Домен добавлен в bypass: example.com
Ошибка конфига: домен уже есть в списке lock
```

## 8. Меню

Меню MVP:

```text
Статус: VPN active, lock off
Применить сейчас
Lock
  Включить lock
  Выключить lock
  Обновить lock
Домены
Домены...
Диагностика
  Запустить test
  Запустить install-check
  Запустить resolve
Выход
```

Требования:

- меню должно обновляться после каждой команды;
- команды должны писать результат в лог и обновлять статус;
- пункт «Домены...» открывает одно окно редактирования;
- в окне две редактируемые таблицы/многострочные области: bypass и lock;
- bypass-список принимает домены, IPv4-адреса и IPv4-диапазоны;
- lock-список принимает домены;
- пользователь может добавить, удалить или перенести домены между списками;
- изменения применяются только после нажатия «Сохранить»;
- при сохранении приложение сравнивает старый и новый состав списков, выполняет пакетное изменение конфигурации и затем применяет правила;
- прямое открытие/редактирование config-файла не входит в MVP; изменение списков доменов выполняется только через формы добавления/удаления.

## 9. Формы доменов и bypass-IP

Нужны простые формы ввода:

- добавить один или несколько доменов в bypass;
- добавить один или несколько IPv4-адресов/диапазонов в bypass;
- добавить один или несколько доменов в lock;
- удалить домен из bypass;
- удалить IPv4-адрес/диапазон из bypass;
- удалить домен из lock.

Допустимые bypass-записи:

```text
example.com
93.184.216.34
93.184.216.0/24
93.184.216.10-93.184.216.20
```

Валидация:

- обрезать пробелы по краям;
- домены показывать в предпросмотре в нижнем регистре;
- IPv4-записи показывать в нормализованном виде;
- запрет пустой строки;
- для IPv4 разрешить одиночный адрес, CIDR и диапазон через дефис;
- некорректный IP, CIDR или диапазон показывать как ошибку до запуска `pkexec`;
- IPv6 в bypass-IP для tray MVP не поддерживается;
- пользовательский ввод отправляется в CLI, а окончательная валидация остаётся за `vpn-killswitch config ...`;
- если домен уже есть в другом списке, основной CLI вернёт `unchanged`/`error`, приложение покажет понятное сообщение.

Текущие одиночные команды:

```bash
pkexec vpn-killswitch config add-bypass DOMAIN
pkexec vpn-killswitch config add-lock DOMAIN
pkexec vpn-killswitch config remove-bypass DOMAIN
pkexec vpn-killswitch config remove-lock DOMAIN
pkexec vpn-killswitch enforce tray
```

Они допустимы только для одиночных действий из меню/формы. При сохранении списка из редактора приложение не должно запускать отдельный `pkexec` на каждую запись.

Требуемый пакетный сценарий:

```bash
pkexec vpn-killswitch config apply-tray --enforce
```

Ожидаемый контракт пакетной команды:

- tray передаёт полный желаемый состав bypass/lock или вычисленную дельту через stdin/временный файл, выбранный при реализации;
- команда валидирует все изменения до записи конфига;
- команда применяет изменения к конфигу;
- при `--enforce` команда сразу выполняет применение правил;
- весь сценарий требует не больше одного запроса пароля.

После успешного добавления/удаления приложение должно запускать применение сразу. Для массового сохранения применение выполняется внутри пакетной привилегированной операции.

## 10. Модель привилегий

MVP:

- `status`, `resolve`, `test`, `install-check` выполняются напрямую;
- `enforce`, `lock enable`, `lock disable`, `lock refresh`, `config add/remove` выполняются через `pkexec`.
- сохранение редактора списков выполняется одной пакетной командой через `pkexec`.

Команды через `pkexec`:

```bash
pkexec vpn-killswitch enforce tray
pkexec vpn-killswitch lock enable tray
pkexec vpn-killswitch lock disable tray
pkexec vpn-killswitch lock refresh tray
pkexec vpn-killswitch config add-bypass DOMAIN
pkexec vpn-killswitch config add-lock DOMAIN
pkexec vpn-killswitch config remove-bypass DOMAIN
pkexec vpn-killswitch config remove-lock DOMAIN
pkexec vpn-killswitch config apply-tray --enforce
```

UX требования:

- не запускать несколько `pkexec` одновременно;
- пока `pkexec` активен, изменяющие пункты меню отключены;
- отменённый запрос пароля не считается ошибкой системы;
- после успешной изменяющей команды сразу обновить статус;
- одиночное добавление/удаление может использовать отдельную config-команду и затем `enforce`;
- массовое сохранение из редактора не должно вызывать `pkexec` на каждую добавленную/удалённую запись;
- массовое сохранение из редактора при `auto_enforce_after_config_change=true` должно применить config + enforce в одной привилегированной операции;
- один пользовательский сценарий сохранения должен требовать не больше одной аутентификации.

Будущее улучшение:

- policy для polkit с разрешением только конкретных действий;
- DBus/systemd-helper вместо прямого `pkexec`;
- без пароля для ограниченных действий, если пользователь входит в доверенную группу.

## 11. Опрос состояния

Опрос состояния в MVP:

- интервал: 5 секунд;
- таймаут команды: 3 секунды;
- если команда статуса зависла или упала, приложение переходит в серый/`offline`;
- при ручном обновлении статус читается сразу.

Чтобы не спамить:

- обновлять иконку/tooltip только при изменении нормализованного состояния;
- одинаковую ошибку не повторять чаще одного раза в 60 секунд.
- первый цикл опроса после запуска только устанавливает базовое состояние;
- после любой ручной команды обновлять статус немедленно, не дожидаясь следующего цикла опроса.

## 12. Путь к CLI

Поиск `vpn-killswitch`:

1. Значение настройки `command_path`, если задано.
2. `/usr/local/sbin/vpn-killswitch`.
3. `vpn-killswitch` из `PATH`.

Если бинарь не найден:

- иконка серая/`offline`;
- подсказка: `vpn-killswitch not found`;
- меню содержит «Выход» и «Настройки»/«О программе».

## 13. Настройки приложения в трее

Пользовательский конфиг:

```text
~/.config/vpn-killswitch-tray/config.toml
```

MVP настройки:

```toml
command_path = "/usr/local/sbin/vpn-killswitch"
config_path = "/etc/vpn-killswitch/config.toml"
poll_interval_seconds = 5
auto_enforce_after_config_change = true
log_file = "~/.local/state/vpn-killswitch-tray/tray.log"
```

Если конфига приложения в трее нет, используются значения по умолчанию.

## 14. Технологии

Предпочтительно Go, чтобы остаться в той же экосистеме.

Выбор технологий для MVP:

- системный трей: `github.com/getlantern/systray`;
- редактор доменов: `yad`;
- выполнение команд: собственный исполнитель с таймаутом;
- config: TOML.

Поведение при отсутствии компонентов:

- если `yad` отсутствует, отключить редактор доменов;
- если backend системного трея не стартует, завершиться с понятной ошибкой в stderr/логе.

## 14.1 Логирование приложения в трее

Лог приложения в трее:

```text
~/.local/state/vpn-killswitch-tray/tray.log
```

Писать:

- старт/завершение;
- выбранный путь к `vpn-killswitch`;
- ошибки `status`/парсинга JSON;
- ошибки `pkexec`;
- отсутствие опциональных инструментов (`yad`, `zenity`, `kdialog`);
- выполненные изменяющие действия без записи паролей/секретов.

Сборка:

```bash
go build -buildvcs=false -o vpn-killswitch-tray ./cmd/vpn-killswitch-tray
```

Запуск:

```bash
./vpn-killswitch-tray
```

## 16. Безопасность

Запрещено в MVP приложения в трее:

- `vpn-killswitch uninstall`;
- очистка старых артефактов;
- purge-режим;
- произвольный ввод shell-команд;
- редактирование nft/systemd напрямую.

Все изменения должны идти только через проверенные команды `vpn-killswitch`.

## 17. План работ

Этап 1: проектирование

- утвердить UX приложения в трее и меню;
- утвердить модель привилегий;
- выбрать библиотеки для tray и форм.

Этап 2: внутренняя логика приложения в трее

- исполнитель команд;
- парсер JSON статуса;
- нормализация состояния;
- подавление повторяющихся записей об ошибках;
- загрузчик настроек.

Этап 3: интерфейс в трее

- состояния иконки;
- меню;
- опрос состояния;
- ручное обновление/применение;
- меню диагностики.

Этап 4: формы доменов

- добавление/удаление домена bypass;
- добавление/удаление IPv4-адреса или диапазона bypass;
- добавление/удаление домена lock;
- автоматическое применение после изменения конфига.
- пакетное сохранение редактора через один `pkexec`.

Этап 5: упаковка/автозапуск

- desktop entry;
- README;
- опциональный install-скрипт.

## 18. Критерии готовности MVP

- приложение в трее запускается как обычный пользователь;
- показывает корректный текущий статус;
- меняет иконку при смене состояния VPN/lock;
- показывает смену режима через иконку и меню;
- умеет добавить домены в bypass списком;
- умеет добавить IPv4-адреса и диапазоны в bypass списком;
- умеет добавить домены в lock списком;
- умеет удалить домен из списков;
- умеет удалить IPv4-адрес или диапазон из bypass;
- умеет выполнить «Применить сейчас»;
- при сохранении редактора не спрашивает пароль многократно;
- не содержит опасных действий;
- работает вместе с уже установленным `vpn-killswitch`.
- не выполняет лишних действий на первом чтении состояния;
- после изменения домена сразу обновляет статус;
- при отсутствии `pkexec` остаётся полезным индикатором только для чтения;
- при отсутствии механизма форм явно отключает действия с доменами;
- пишет собственный лог для диагностики проблем приложения в трее.
